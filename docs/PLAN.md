## Working agreements

- External services run **locally or mocked** until real credentials are added to the environment:
  MongoDB → Docker `mongo` replica set / `mongodb-memory-server` in tests; Resend, Inngest, R2, AI, Stripe → adapters with in-memory fakes selected by env (`*_MODE=fake`).
- Every env var is still declared in `lib/env.ts`; plugging in real creds must need no code change.

- 2026-09-29 — Phase 7c (tours, trash, cleanup) landed. Decisions: **Permanent delete** (`lib/deletion/purge.ts`, one path for Delete permanently, Empty trash, `bulk-delete`, `purge-trash`, cleanup rules and connection data removal) works in this order: scheduled/queued emails are canceled in Resend first (one Resend will not cancel is kept and reported as skipped), then the R2 objects are deleted, then one transaction writes the tombstones and removes contents, attachments, webhook events, emails and emptied threads (counters of other threads recomputed). R2 goes before the documents (TRD §2.14 says after commit): if R2 fails, the documents still name the keys and the next run retries, the other order would orphan objects for good. Rollups and `usage_periods` are never touched. Tombstones (`lib/deletion/tombstones.ts`) are kind-aware (`sent_email` / `received_email`, per connection); `process-event` ignores late events (`ignoredReason: deleted`, still counted in insights), threading starts a new thread for a reply to a deleted Message-ID, and `syncedEmailsToImport()` is the filter the sync email backfill must call once it exists (that stage is still empty, see Phase 4 follow-ups; tested in isolation). **Bulk** (`lib/deletion/bulk.ts`): a request snapshots the filter and a cap time into `bulk_operations` (new collection, TTL 7 days; `emails`/`threads` got `trashedByOpId` so Undo restores exactly what an operation moved); up to 100 items run inline, more go to the `bulk-delete` job (batches of 500 ordered by `_id`, one transaction each, cursor advances only after a batch succeeded, retried or duplicate steps are idempotent, one audit entry at the end, `bulk:<id>` realtime event plus polling for the progress card); "select all matching" exists for Inbox, Trash and Activity (not for the unread filter, which is per member, nor Sent); permanent bulk delete needs the typed count and the server re-checks it against the current count. Permissions: trash/restore follow `thread:trash` / `email:trash`, everything permanent is `email:delete` (Owner/Admin), the service enforces them (`orgAction` without a permission). **Retention** (`lib/deletion/retention.ts`, daily): per org `getRetentionDays(orgId)` from `lib/billing/entitlements` (plan or override) cuts at `createdAt < now - days` (an upgrade lengthens retention at once), R2 first, no tombstone (sync never imports mail older than the window); a second pass removes bodies and files whose email a TTL index already dropped. **Cleanup rules**: `cleanup_rules` as in DBD; rules need `olderThanDays`, `block_sender` needs an address or domain and always trashes; editing, toggling or deleting a rule that deletes needs `cleanupRule:manageDelete` too (a Developer cannot turn a rule into a delete rule); the hourly job skips drafts and scheduled mail, trashes with `trashedByRuleId`, archives threads once; `block_sender` is applied in `fetch-inbound` (mail goes straight to Trash, no notification, no triage). **Connection removal**: `removeConnection` takes `deleteSyncedData` + typed `DELETE`; the `delete-connection-data` job (files first, then mail, then leftovers and the ten mirror collections, every query scoped by `orgId` and `connectionId`; rollups and senders stay) with a `connection.data_deleted` audit entry; development without an Inngest server runs it in-process. **Tours**: NextStepjs 2.3 works with Next 16 and motion 13 (peer ranges fine, no Driver.js needed). The provider (`NextStepProvider` + context in the org layout) is light; the runner (NextStep, card, Wizi) is `next/dynamic` with `ssr: false` and renders NextStep without children because it only needs the document. Targets are `data-tour` attributes only; the sidebar step uses `nav-button` below 1000 px; below 640 px the card is a portal bottom sheet (a transformed ancestor would break `position: fixed`); steps for permissions the member lacks are dropped on the server, a step on the current page whose target is missing (the connect card once connected) is dropped at start, fewer than two steps means no tour; auto start only on the overview of an org without a connection, 2 s after load, when no dialog or the composer is open, at most once per page view, never again once started, completed or skipped unless the major version rises; progress is saved from `onStart`/`onStepChange`/`onComplete`/`onSkip` (start is guarded against re-render duplicates); Help (?) menu in the top bar lists tours with completion checks and Replay (navigating to the first step's page first), the user menu has "Restart product tour" (also closes the mobile sheet); finishing the welcome tour for an org without a connection opens Settings → Connections with the Connect dialog (`?connect=1`). Wizi's mood travels in the step's `icon`; the card wraps Wizi in its own `MotionProvider` because NextStepjs renders outside the shell's `LazyMotion strict`. Verified in Chromium against `next dev` with the Inngest dev server (screenshots in the session scratchpad `p7c/`): welcome tour end to end incl. keyboard, skip, Escape, replay from another page, mobile; trash, Undo, permanent delete, Empty trash with typed count, select-all-matching progress card, late `email.opened`/`email.received` for deleted mail ignored; cleanup rule create/preview and the `cleanup-rules`, `purge-trash`, `retention` crons invoked through Inngest; removal with data deletion. - 2026-09-29 — Phase 7a (AI) landed. Decisions: `lib/ai/client.ts` is the only door to a model (`openai` SDK, Chat Completions, `AI_BASE_URL`/`AI_API_KEY`/`AI_MODEL`/`AI_MODEL_FAST`, 20 s fast / 45 s main timeout, SDK retries 2); it asks for `json_schema` structured output (size keywords stripped) and learns from a 400 to drop `json_schema`, switch to `max_completion_tokens` or drop `temperature`, remembering only what worked; every answer goes through a Zod-validated parser (fences and chatter tolerated), failures are `ai_bad_output` / `ai_unavailable` and are never charged. `AI_MODE=fake` is a deterministic client (`lib/ai/fake.ts`, `[[ai-fail]]` in the input forces a failure). Prompts (`lib/ai/prompts/*`, versioned, stored on `ai_usage.promptVersion`) send only the newest text: quoted history (`>`, "On ... wrote:", Outlook headers), signatures and mobile footers stripped, bodies cut to 2,000 (triage) / 1,500 per message with the last 4 messages (draft) / 4,000 (compose) characters, no attachments, no recipient lists; third-party text is wrapped in delimiters with defused look-alikes and an "untrusted data" notice; anomaly explanations get only rollup counts, bounce kinds, recipient domains and provider reasons with addresses redacted.
