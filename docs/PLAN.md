## Working agreements

- External services run **locally or mocked** until real credentials are added to the environment:
  MongoDB → Docker `mongo` replica set / `mongodb-memory-server` in tests; Resend, Inngest, R2, AI, Stripe → adapters with in-memory fakes selected by env (`*_MODE=fake`).
- Every env var is still declared in `lib/env.ts`; plugging in real creds must need no code change.
- Each phase ends green: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`.

- 2026-09-29 — Phase 6a (domains, DNS check, API keys, UI fixes) landed. Decisions: domains live at `/[org]/domains[/id]` and keys at `/[org]/api-keys` (nav already pointed there); permissions follow the matrix (tracking = `domain:update`, verify = `domain:verify`, add = `domain:create`, delete = `domain:delete`, project assignment = `project:update`, keys: `apiKey:create` for full access, `apiKey:create` or `apiKey:createSending` for sending keys, `apiKey:delete`). Every change goes to Resend first, then the mirror; deleting a domain removes the mirror and recomputes senders (they become `domain_unverified`) and notifies members with `domain:update` when senders or queued emails are affected. DNS check (`lib/dns`, `lib/services/dns-check.ts`): `node:dns/promises` with a hard timeout (3 s, one try), verdicts `pass|fail|missing|unknown|skipped` per SPF/DKIM/DMARC/MX stored on `domains.dnsCheck` with per-record details; DMARC is looked up on the domain then its parents; `unknown` (lookup failed) never alerts; on-demand checks are rate limited to one per domain per 10 s. Drift: the existing `domain_status` rule now also fires for a `verified` domain whose SPF or DKIM verdict is `fail`/`missing` ("lost DNS records"), and resolves when the records return; the daily `dns-check` cron (04:17 UTC) requests one alert evaluation per org. API key secrets: returned once from `createApiKey`, kept only in the dialog's state, never stored, logged, audited or published (tested against every collection). The key Wisemail uses: the fake adapter knows its own key id (`ownApiKeyId`), so it is blocked outright; live Resend does not expose it, so a key named like "Wisemail" that we did not create is flagged "may be used by Wisemail" and needs an explicit acknowledgement (last4 of the connection key shown). Adapter gained `createDomain`, `verifyDomain`, `removeDomain`, `createApiKey`, `removeApiKey`, `ownApiKeyId`. UI fixes: breadcrumb labels come from a small client context (`BreadcrumbLabel` rendered by the page; ids show as an ellipsis until labelled); thread and sent rows show display names (`peopleLabels`, looked up from the thread's emails, address as fallback); topbar search collapses to an icon below 1200 px and the breadcrumb truncates without wrapping; the live dot shows in the bar below 1000 px. `/api/stream`: could not reproduce the "destination stream closed early" log against the route (curl and Chromium aborts, 25 rapid connect/abort cycles); that message is React's page-render abort handler (seen here right after an unrelated 500 on a page render), so the route now answers already-aborted requests with an empty 499, treats every disconnect-shaped error as routine and stays quiet in `cancel`, with tests. Follow-ups: verification of a live domain is asynchronous in Resend (Verify now returns whatever Resend reports at that moment; `domain.updated` events settle it), API key `permission`/domain are unknown for keys created outside Wisemail (Resend's list omits them), key rotation is a written checklist only, no bulk domain actions, drift alerts need an enabled `domain_status` rule, project scope for API keys only reveals domain-limited keys.

- 2026-09-29 — Phase 6b (audience, templates, broadcasts) landed. Decisions: every write goes to Resend first through the adapter and only then updates the mirror, the audit log and the realtime topics in one transaction (`lib/services/audience-shared.ts`: `loadConnection` needs an `active` connection, `remote()` maps Resend errors to `rate_limited` / `resend_rejected` / `connection_inactive`, one inline 429 retry); a Resend failure leaves the mirror untouched (tested per resource), "already gone in Resend" counts as deleted. Permissions follow the matrix: contacts `contact:*` (Support may only unsubscribe; resubscribing needs `contact:update`), segments/topics/properties `audience:*`, templates `template:*`, broadcasts `broadcast:*` (deleting a draft = `broadcast:create`; cancel, delete of scheduled and remove of sent = `broadcast:send`). Project-scoped members see only audience objects of connections that own a domain in their projects (objects carry no project of their own). Contacts: list sorted by address with a cursor (`/api/v1/contacts`), engagement on the detail page is computed from our `emails` (no cache), segment counts are recounted from the mirror after every membership change. CSV: parsed and validated in the browser (`lib/audience/csv.ts`, column mapping, per-line problems, downloadable), sent in batches of 25 with ~8 calls/s pacing and progress; above 500 rows the rows are uploaded once into `contact_imports` and the throttled `import-contacts` job works through them (per-batch progress, a lasting 429 stops the batch and the job sleeps; without an Inngest dev server in development it runs in-process); the audit entry is written once per import. Templates: variables are `{{{NAME}}}`, undeclared ones in the HTML are auto-declared (text, no default), a published template is re-published on every save (Resend only sends the published version), edits use optimistic concurrency (`conflict`), duplicating copies into any writable connection as a draft. Composer Template mode: only published templates on the sender's own connection are offered, variables without a default are required, `sendEmail` gained `templateId` + `templateVariables` (the email keeps `templateId`/`templateVariables` and a rendered copy of the body for our own views; `deliverEmail` sends `template: { id, variables }` to Resend, no html), drafts persist the choice. Broadcasts: created in Resend as a draft on first save, every save updates it there; "Start from a template" copies the template HTML (Resend's broadcast API takes no template id); send checks the sender, the audience (mirrored contacts in the segment, minus unsubscribed and topic opt-outs; empty blocks the send) and shows the audience size in a confirm dialog; the mirror takes the status Resend reports after send or cancel (`queued` + future time = `scheduled`); the `send-broadcast` job follows a broadcast until it is sent, failed or canceled (sleeps until the scheduled time, then polls); stats are counted from `emails.broadcastId` (recipients, delivered, opened (estimate), clicked, bounced, complaints); a missing unsubscribe link is a warning with an "add footer" button. Adapter gained contact, segment, topic, property, template and broadcast write methods (live + fake); the fake settles a scheduled broadcast to `sent` once its time has passed. `orgAction` now turns `ForbiddenError` from a service into a `forbidden` result. Follow-ups: Resend's contact list has no topic/segment filters, so a contact's topic choices only refresh on sync or edit; unsubscribe counts per broadcast are not tracked; broadcast test sends are ordinary emails (not linked to the broadcast); no "send test" recipient picker; template `replyTo` is not editable; rich text mode cannot hold the unsubscribe placeholder as a link (the footer button inserts it as text); contacts keep the `engagement` cache field unused; automations UI (P1) not built.
